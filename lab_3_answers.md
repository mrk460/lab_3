# Лабораторна робота №3: Робота з CSS. Відповіді на питання

## Частина 1. Вступ до CSS

**1. Які існують методи підключення CSS і в чому різниця між ними?**

Є три способи.

- **Вбудований (inline)**: атрибут `style` на елементі, наприклад `<p style="color: red;">`. Діє лише на цей елемент, має найвищий пріоритет серед звичайних правил, але його неможливо перевикористати, і він змішує розмітку зі стилями.
- **Внутрішній (internal)**: елемент `<style>` у `<head>`. Діє на всю сторінку, але не кешується окремо й не може бути спільним для кількох сторінок.
- **Зовнішній (external)**: окремий `.css`-файл, підключений через `<link rel="stylesheet" href="styles.css">`. Один файл стилізує весь сайт, браузер його кешує. Це основний спосіб для реальних проєктів.

**2. Різниця між селектором класу та ID. Коли що використовувати?**

Клас (`.card`) можна застосовувати до багатьох елементів, а один елемент може мати кілька класів. ID (`#contacts`) має бути унікальним на сторінці, а специфічність у нього значно вища. Класи слід використовувати для стилізації повторюваних елементів (картки, кнопки, теги). ID доречний для унікальних блоків, якорів (`href="#top"`) і зв'язків із JavaScript чи мітками форм. Для стилізації його краще уникати, бо важко перевизначити.

**3. Що таке Box Model і які властивості вона містить?**

Кожен елемент є прямокутною коробкою з чотирьох шарів, від центру назовні: **content** (вміст), **padding** (внутрішній відступ), **border** (межа), **margin** (зовнішній відступ, прозорий). Ширина `width` за замовчуванням (`content-box`) задає лише вміст, а padding і border додаються зверху, тому повна ширина більша. Із `box-sizing: border-box` задана ширина включає content, padding і border, що значно спрощує розрахунки макета. Вертикальні margin сусідніх блоків можуть згортатися (margin collapsing): береться більший із двох.

**4. Що таке специфічність і як вона визначається?**

Специфічність визначає, яке правило перемагає, коли до одного елемента застосовано кілька конфліктних. Її рахують як набір із чотирьох рівнів (від вищого до нижчого):

1. inline-стилі (`style="..."`): `1,0,0,0`
2. ID-селектори: `0,1,0,0`, наприклад `#contacts`
3. класи, атрибути, псевдокласи: `0,0,1,0`, наприклад `.entry`, `a[href^="https"]`, `:hover`
4. теги й псевдоелементи: `0,0,0,1`, наприклад `p`, `::after`

Приклади: `p` = (0,0,0,1); `.entry p` = (0,0,1,1); `#main .entry:hover` = (0,1,2,0). Якщо специфічність однакова, перемагає правило, що йде пізніше. `!important` перекриває все, але його варто уникати. Універсальний селектор `*` специфічності не додає.

**5. Як вплинути на позиціювання за допомогою `display` і `position`?**

`display` задає тип коробки: `block` (займає весь рядок), `inline` (у потоці тексту, без width/height), `inline-block`, `none` (елемент прибирається), `flex`, `grid`. `position` задає спосіб розташування: `static` (за замовчуванням), `relative` (зсув відносно власного місця через `top/left`), `absolute` (відносно найближчого позиціонованого предка), `fixed` (відносно вікна), `sticky` (звичайний потік до певної межі прокрутки, потім прилипає). Порядок накладання керується `z-index`.

**6. Різниця між Flexbox та CSS Grid.**

Flexbox одновимірний: він розкладає елементи в один рядок або стовпчик, а розміри визначаються вмістом (`flex-grow`, `flex-shrink`, `flex-basis`). Підходить для панелей навігації, рядків із тегами, вирівнювання всередині компонента. Grid двовимірний: задає рядки й стовпці одночасно (`grid-template-columns`, `grid-template-areas`) і розміщує елементи за сіткою. Підходить для макета всієї сторінки. На практиці їх поєднують: Grid для каркаса, Flexbox усередині блоків (як у цій роботі).

**7. Як працюють псевдокласи?**

Псевдоклас описує стан або положення елемента, а не його ім'я чи клас, і записується через двокрапку.

- `:hover`: курсор над елементом. `a:hover { color: orange; }`
- `:focus` / `:focus-visible`: елемент у фокусі (клавіатура, поле вводу). `input:focus { outline: 2px solid blue; }`
- `:active`: елемент натиснуто в цей момент. `button:active { transform: scale(0.97); }`
- Структурні: `:first-child`, `:last-child`, `:nth-child(2n)`, `:first-of-type`.

**8. Як змінити стилізацію для різних пристроїв і розмірів екрана?**

За допомогою медіазапитів: `@media (max-width: 720px) { ... }`. Для коректної роботи на мобільних у `<head>` потрібен `<meta name="viewport" content="width=device-width, initial-scale=1">`. Також допомагають відносні одиниці (`rem`, `%`, `vw`), гнучкі макети на Flexbox/Grid (`flex-wrap`, `minmax()`), `max-width` для зображень. Поширений підхід mobile-first: базові стилі для вузького екрана, а `min-width` запити додають складніші макети для широких.

**9. Для чого префікси `-webkit-` / `-moz-` і чи потрібні вони сьогодні?**

Вендорні префікси браузери додавали до експериментальних або ще не стандартизованих властивостей (`-webkit-transition`, `-moz-appearance`), щоб розробники могли їх пробувати до остаточного стандарту. У сучасній розробці вручну їх писати майже не потрібно: більшість властивостей уже стандартизовані й працюють без префіксів. Для рідкісних випадків застосовують Autoprefixer (або вбудовану обробку в збирачах і в Tailwind v4), який додає потрібні префікси автоматично за списком цільових браузерів. Є винятки, де префікс ще реально потрібен (наприклад, `-webkit-line-clamp`, `-webkit-text-stroke`).

**10. Як організувати CSS, щоб він був читабельним і підтримуваним?**

- Ділити файл на секції з коментарями-заголовками (змінні, базові стилі, макет, компоненти, адаптивність), як у `styles.css` цієї роботи.
- Виносити кольори, відступи, шрифти в CSS-змінні (`:root { --accent: ... }`).
- Дотримуватися єдиної схеми іменування (наприклад, BEM: `.card__title--active`).
- Писати селектори з низькою специфічністю: переважно класи, без ID і `!important`.
- Групувати властивості в одному порядку (макет, box model, типографіка, візуальні ефекти).
- Починати з reset/base-стилів, потім загальні блоки, потім специфічні; медіазапити розміщувати в кінці або поруч із відповідним компонентом.
- Не дублювати код: спільні стилі виносити в один клас.
- Коментувати «чому», а не «що»: нетривіальні рішення, обхідні шляхи для багів.

## Частина 2. Tailwind CSS

**1. Основна різниця між Tailwind CSS та Bootstrap / Material UI.**

Bootstrap і Material UI дають готові компоненти (кнопки, навігаційні панелі, картки) із наперед заданим виглядом, тому сайти легко стають схожими один на одного, а кастомізація вимагає перевизначення стилів. Tailwind дає низькорівневі утилітарні класи (`flex`, `p-4`, `text-center`), з яких розробник сам збирає будь-який дизайн, не пишучи власного CSS. Компонентів «з коробки» немає, але немає й обмежень по вигляду.

**2. Як `@tailwindcss/vite` спрощує налаштування порівняно зі застарілою конфігурацією?**

У Tailwind v3 потрібно було встановлювати `postcss` і `autoprefixer`, створювати `tailwind.config.js` та `postcss.config.js`, вказувати в `content` шляхи до файлів, де шукати класи, і підключати три директиви `@tailwind base/components/utilities`. У v4 достатньо встановити пакет, додати плагін `tailwindcss()` у `vite.config.js` і написати один рядок `@import "tailwindcss";`. Файли, у яких використовуються класи, плагін знаходить автоматично, а обробка CSS і префікси вбудовані. Плагін також інтегрується безпосередньо у Vite, що дає швидшу збірку.

**3. Що робить директива `@import "tailwindcss";`?**

Вона підключає всі шари Tailwind: **preflight** (базове скидання стилів браузера), **theme** (змінні дизайну: кольори, шрифти, відступи) та **utilities** (утилітарні класи). Під час збірки Tailwind сканує вихідні файли проєкту й додає до підсумкового CSS лише ті класи, які реально використовуються, тому результат маленький.

**4. Як застосувати псевдокласи `hover`, `focus` у Tailwind?**

Через префікси-варіанти перед назвою утиліти, розділені двокрапкою: `hover:bg-blue-700`, `focus:ring-2`, `focus-visible:outline-2`, `active:scale-95`. Варіанти можна поєднувати з адаптивними: `md:hover:bg-slate-100`. Для груп є `group` та `group-hover:`, для станів дочірніх елементів `first:`, `last:`, `odd:`. У цій роботі, наприклад: `hover:scale-105`, `hover:bg-slate-100`, `first:border-t-0`.

**5. Як налаштувати власні токени дизайну (кольори, шрифти) у Tailwind v4?**

Через CSS-директиву `@theme` прямо в CSS-файлі, без `tailwind.config.js`:

```css
@import "tailwindcss";

@theme {
  --color-ink: #16232b;
  --color-brand: #0b6e8a;
  --font-display: Georgia, "Times New Roman", serif;
}
```

Кожна змінна з відповідним префіксом (`--color-*`, `--font-*`, `--spacing-*`, `--breakpoint-*`) автоматично створює утиліти: `bg-ink`, `text-brand`, `font-display`. Це використано в `src/index.css` цієї роботи.
